# Хрестики-нулики 5 в ряд (Гомоку): Minimax + альфа-бета

Гра-головоломка з комп'ютерним суперником на полі 15×15. Людина грає ✕, комп'ютер — ◯.
Перемагає той, хто першим збере 5 каменів в ряд (горизонталь, вертикаль, діагональ).

## Структура
- `backend/`  — Python + FastAPI: алгоритм ШІ (`ai.py`) і REST API (`main.py`)
- `frontend/` — HTML/CSS/JS: інтерфейс, звертається до API

## Запуск
Бекенд:

    cd backend
    pip install -r requirements.txt
    uvicorn main:app --reload --port 8000

Фронтенд (в іншому терміналі):

    cd frontend
    python -m http.server 5500

Відкрити http://localhost:5500

## Архітектура та API
Фронтенд зберігає дошку, малює її і не містить логіки ШІ. Після ходу людини він надсилає запит:

    POST /api/move
    {"board": [225 чисел: 0 — порожньо, 1 — людина, 2 — ШІ], "depth": 3, "alpha_beta": true}

Бекенд не зберігає стан між запитами (stateless). Він перевіряє, чи не виграла вже людина, шукає хід ШІ
і повертає: `status` (ongoing / human_won / ai_won / draw), `move` [рядок, стовпець], `value` (оцінка ходу),
`nodes` (кількість вузлів дерева), `cuts` (кількість відсікань), `time_ms`, `root_moves`, `winning_line`.
Swagger-документація: http://localhost:8000/docs

## Як працює ШІ

### 1. Дерево рішень і Minimax
Гра моделюється як дерево: вузол — позиція на дошці, ребро — хід, рівні чергуються між ходом ШІ та ходом людини.
Глибина дерева (за замовчуванням 3 напівходи) — це на скільки ходів уперед «бачить» ШІ.

- Вузли ШІ — **MAX**: ШІ обирає хід із найбільшою оцінкою.
- Вузли людини — **MIN**: припускаємо, що людина відповідає найкращим для себе (найгіршим для ШІ) ходом.
- Оцінка вузла — це значення, яке «піднімається» від листків до кореня; у корені ШІ обирає хід із найкращою оцінкою.

### 2. Евристична оцінка позиції (листки дерева)
Дерево до кінця гри побудувати неможливо, тому на межі глибини позиція оцінюється функцією.
Поле розбивається на всі «вікна» з 5 клітинок (у 4 напрямках). Для кожного вікна, у якому є камені
лише одного гравця, додаються бали залежно від їх кількості (1, 2, 3, 4, 5 каменів → 1, 10, 100, 1000, 10⁶).
Вікна зі змішаними каменями дають 0, бо там п'ятірку вже не зібрати.
Камені ШІ дають бали зі знаком «+» (вага 5), камені людини — зі знаком «−» (вага 6).
Захист трохи важливіший за напад, тому ШІ вчасно блокує відкриті трійки й четвірки.

Термінальні стани: якщо хід приводить до п'ятірки, оцінка дорівнює ±(10⁷ + залишкова глибина).
Додаток глибини змушує ШІ вибирати найшвидшу перемогу й відтягувати поразку.

**Інкрементальна оцінка.** Повний перерахунок усіх вікон на кожному вузлі занадто повільний для Python.
Тому оцінка зберігається в об'єкті гри й оновлюється при кожному ході/відкаті: перераховуються лише вікна
(до 20), що містять змінену клітинку.

### 3. Альфа-бета відсікання
Альфа — найкраща оцінка, яку вже гарантовано має MAX, бета — найкраща для MIN.
Якщо в якомусь вузлі стає β ≤ α, решта його дітей не може вплинути на результат, і гілка відсікається.
Результат Minimax при цьому **не змінюється**, але кількість оглянутих вузлів різко зменшується:
у найкращому випадку з O(bᵈ) до приблизно O(b^(d/2)), де b — коефіцієнт розгалуження, d — глибина.

Експеримент (тестова позиція, глибина 4):

| Режим                | Вузлів дерева | Відсікань | Час      | Обраний хід |
|----------------------|---------------|-----------|----------|-------------|
| Minimax без відсікань| 11 110        | 0         | ≈ 1050 мс| однаковий   |
| Альфа-бета           | 440           | 136       | ≈ 60 мс  | однаковий   |

### 4. Обмеження перебору (щоб гра була швидкою)
Поле 15×15 дає до 225 ходів на вузол, що неприпустимо багато. Тому:

1. **Кандидати ходів** — лише порожні клітинки в радіусі 2 від уже поставлених каменів
   (лічильник сусідів оновлюється при кожному ході). На порожній дошці ШІ ходить у центр.
2. **Впорядкування ходів** — кандидати сортуються за швидкою евристикою клітинки: довжина лінії, яку
   утворює камінь, і кількість відкритих кінців, окремо для ШІ та людини (бали людини з коефіцієнтом 0,9,
   бо блокування теж важливе).
3. **Обмеження ширини** — розглядаються лише 10 найкращих кандидатів (`WIDTH`).

Пункт 2 також підвищує ефективність відсікання: чим раніше розглядається сильний хід, тим раніше
спрацьовує умова β ≤ α.

### 5. Алгоритм вибору ходу (`best_move`)
1. Якщо дошка порожня — хід у центр.
2. Побудувати впорядкований список кандидатів.
3. Для кожного кандидата: зробити хід; якщо це перемога — оцінка 10⁷ + глибина, інакше викликати
   `search(depth − 1)` для відповіді людини; відкотити хід.
4. Оновлювати α у корені й запам'ятовувати хід із найвищою оцінкою.
5. Повернути хід і статистику (вузли, відсікання, час).
